# Master Backend Developer Requirements & Feature Audit

## 1. Overview
This directory contains modular backend requirement specifications generated by auditing the `niklo-partner` Flutter app code (`lib/features`) against the microservices backend (`niklo-main`).

---

## 2. Microservice Mapping Matrix

| App Module | Frontend Feature Area | Primary Backend Microservice (`niklo-main`) | Key Realtime / REST Transport |
| :--- | :--- | :--- | :--- |
| **Auth & Common** | Login, OTP, Sign-up, Language, Profile | `auth-service` & `user-service` | REST APIs (`/api/v1/auth`, `/users`) |
| **Car Driver** | Onboarding, Live Map, Rides, Trips, Wallet | `ride-service`, `driver-service`, `payment-service` | Realtime Sockets (`SocketClient`) + REST (`/ride`, `/driver`) |
| **Bus Operator** | Fleet, Routes, Schedules, Seats, Manifest | `bus-service` | REST APIs (`/api/v1/bus/...`) |
| **Hotel Partner**| Properties, Rooms, Bookings, Calendar, Offers | `hotel-service` & `booking-service` | REST APIs (`/hotels/...`, `/bookings/hotel/...`) |

---

## 3. High-Level Static vs Dynamic Audit

| Module | Dynamic (Fully Backend Integrated) | Static / Mocked (Action Required) |
| :--- | :--- | :--- |
| **Auth & Profile** | • Send OTP & Verify OTP<br>• JWT Authentication<br>• Profile Fetch (`GET /users/profile`) | • Profile Edit (`PATCH /users/profile`) is currently in-memory on the app (`profileEditsProvider`). Backend must implement `PATCH`. |
| **Car Driver** | • Live GPS & Socket Handshake (`driver:go_online`, `driver:location`)<br>• Ride Acceptance (`POST /ride/:id/accept`) & Completion<br>• Trip History (`GET /ride/driver/:id/trips`)<br>• Dynamic Daily Earnings Calculation (`todaysSummaryProvider`)<br>• Wallet Withdraw Request (`POST /payment/wallet/withdraw`) | • Onboarding setup screens (`submit_documents_screen.dart`, `vehicle_registration_screen.dart`, `driver_profile_screen.dart`, `bank_details_screen.dart`) are static UI mockups.<br>• Backend missing `POST /api/v1/driver/bank-details` & `POST /api/v1/ride/driver/go-offline` REST endpoints.<br>• Ride OTP in `ride:start` socket & REST `POST /ride/:id/verify-otp` is unverified by backend.<br>• `ride:new_request` socket payload lacks full address/fare details.<br>• Online Hours counter runs locally in `FlutterSecureStorage`. |
| **Bus Operator** | • Operator Registration (`POST /bus/operators`)<br>• Bus Fleet & Seat Layout Builder<br>• Route & Corridor Management<br>• Schedule Creation & Seat Matrix Lock | • Operator Summary Dashboard (`GET /bus/operators/:id/summary`) needs dedicated aggregation query.<br>• Passenger manifest PDF generation endpoint. |
| **Hotel Partner** | • Property & Room Category CRUD<br>• Bookings & Guest Check-in/Check-out<br>• Occupancy Calendar & Monthly Stats<br>• Offers/Promotions Management<br>• Guest Review Replies | • Fully mapped to `hotel-service` & `booking-service` REST contracts. Requires database migrations for reviews & calendar tables. |
